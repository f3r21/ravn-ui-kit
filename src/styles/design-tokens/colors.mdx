## Border radius

| Token | Value | Verified against |
| --- | --- | --- |
| `--radius-2` | 2px | `Datepicker.md` day-grid cell |
| `--radius-4` | 4px | `Tags00/01.md` chips/pills (most common radius in the kit) |
| `--radius-sm` | 8px | `Button, Switch Button00/01.md` icon buttons |
| `--radius-10` | 10px | `Button, Switch Button00/01.md` segmented-control track |
| `--radius-md` | 16px | `Top Navigation Bar00/01.md` search bar |
| `--radius-lg` | 24px | `ApplicationSidebar00/01.md` inner sidebar |
| `--radius-xl` | 40px | **Unverified** — only ground-truth occurrence is a 40×40px circular button (`border-radius` = half of width/height, i.e. `rounded-full`), not a distinct 40px token. Current consumer (`task-table.tsx`) needs re-checking against its own spec in Chunk 15. |
| `--radius-full` | 9999px | circles/pills |

## Shadows

Only shadows confirmed present on a real shipped component are tokenized. "Drop Shadow Large" (`0 0 72px`) only appears on the Branding guideline documentation page frame itself, never on a product component, so it's intentionally not included.

| `--shadow-nav` | `0px 2px 0px #2c2f33` | `Top Navigation Bar00.md` hard-edge separator |
