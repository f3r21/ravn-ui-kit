# Ravn UI Kit

An accessible, reusable React component library built with **React 19,
TypeScript, Tailwind CSS v4, React Aria** and documented here in Storybook.

Every component in this kit was audited against real Figma ground-truth
exports (component CSS, not eyeballed screenshots) rather than built from
guesses. That audit log is a working document and is not part of the
repository; what outlived it is on the **Decisions** page — the calls that
still govern how this kit is changed — and, per value, in the source itself,
where every colour, radius and shadow cites the export it came from at the
call site (`Dashboard Mockup.md:237-254`, `Cards01.md L552-833`, and so on).

## How this documentation is organized

- **Design Tokens** — the raw color, radius, typography and shadow values
  every component is built from, each one verified against a specific
  ground-truth export. Start here if you're building something new and need
  to know which token to reach for.
- **Primitives** — the smallest reusable building blocks (Button, TextButton,
  Tag, Input, Tabs, SegmentedControl, LabelCheckbox, Badge, Skeleton).
- **Components** — composed pieces built from primitives (Avatar, UserRow,
  Card, TaskCard, ProjectInfo, TaskMetaBadges, Modal and its task-flow variants,
  DatePicker).
- **Layout** — page-level composites (ApplicationSidebar, SidebarItem,
  TopNav, SearchBar, TaskListView, TaskTable, ViewSwitcher, AppShell) that
  assemble the above into the real product screens.

## Installation

```bash
npm install @ravn/ui-kit
```

Styles come from one of two paths, depending on whether your app runs its own
Tailwind CSS v4 build:

- **Your app already uses Tailwind CSS v4 (recommended).** Import the raw token
  stylesheet once at your app's entry point, and add a `@source` directive to your
  own Tailwind entry CSS so it scans this package's compiled output for the utility
  classes components use (`node_modules` is excluded from automatic scanning by
  default):

  ```tsx
  import '@ravn/ui-kit/theme.css';
  ```

  ```css
  @import 'tailwindcss';
  @import '@ravn/ui-kit/theme.css';
  @source "../node_modules/@ravn/ui-kit/dist";
  ```

- **Your app does not run Tailwind CSS.** Import the fully-compiled stylesheet
  instead — it contains every utility class the components actually use, pre-generated:

  ```tsx
  import '@ravn/ui-kit/ui-kit.css';
  ```

  Don't import both — `ui-kit.css` already includes the token layer that `theme.css`
  exposes on its own for the first path.

Then use any component:

```tsx
import { TextButton, Input, Card, Badge } from '@ravn/ui-kit';

export function UserForm() {
  return (
    <Card className="max-w-md mx-auto flex flex-col gap-4">
      <div className="flex justify-between items-center">
        <h2 className="text-lg font-bold text-neutral-5">User registration</h2>
        <Badge variant="success">Active</Badge>
      </div>
      <Input label="Email" placeholder="user@ravn.co" />
      <TextButton variant="primary" onPress={() => console.log('Saved')}>
        Save
      </TextButton>
    </Card>
  );
}
```

Note: `Button` (from `Primitives/Button`) is a fixed 40×40px icon-only control
requiring an `aria-label` — use it for icon buttons, not labeled text CTAs
like the one above.

## Fidelity notes worth knowing

- A semantic color-alias layer (`text-main`, `surface-neutral`, etc., now
  including the `surface-overlay`/`surface-panel`/`surface-shell`
  dark-surface-hierarchy tier — see **Design Tokens → Colors**) and a
  type-scale layer (`text-body-m`, etc. — see **Design Tokens → Typography**)
  now exist and are both fully migrated everywhere the aliased role actually
  applies. A small number of same-color, genuinely-different-role usages are
  deliberately left as raw ramp classes rather than force-fit into an alias
  that would misrepresent their role — see **Design Tokens → Colors** for
  exactly which ones and why.
- Border radii are literal per-component values in the source designs, not a
  clean t-shirt ramp — see **Design Tokens → Colors** for the full token
  table and which real component each one was verified against.
- A handful of primitives (`Skeleton`, `Datepicker`'s native
  `<input type="date">`) have no direct Figma component behind them. They're
  kept because they're genuinely useful and don't contradict anything in the
  spec, not because they were found in an export. A previous `Switch`
  primitive (an iOS-style boolean toggle) was removed after live Figma access
  confirmed the real "Switch button" component isn't a toggle at all — it's a
  single 157px pill/chip (Default/Selected states, no on/off semantic),
  dimensionally identical to `SegmentedControl`'s pill items, which already
  covers this shape. Unlike `Skeleton`/`Datepicker`, this one _was_
  contradicted by spec once checked, so it didn't meet the bar above.
